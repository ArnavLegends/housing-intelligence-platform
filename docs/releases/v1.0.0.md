# V1.0.0 Release Baseline

## 1. What V1 Attempted to Solve

V1 attempted to create an end-to-end housing price intelligence prototype. It connected a housing CSV dataset, an XGBoost regression model, saved model artifacts, a FastAPI inference service, and a Streamlit frontend with analytics and explainability views.

V1 attempted to demonstrate that the project is more than a static website by including a real training script, model artifacts, an API surface, and an interactive dashboard.

## 2. Architecture

V1 contains three main Python entry points:

| Entry point | Purpose |
|---|---|
| `streamlit_app.py` | Interactive frontend and analytics dashboard. |
| `app.py` | FastAPI inference service. |
| `train.py` | Model training and artifact generation. |

The actual Streamlit prediction flow is local:

```text
User
-> Streamlit sidebar inputs
-> build_payload()
-> run_prediction_flow()
-> fetch_prediction()
-> artifacts/housing_model.joblib
-> pipeline.predict()
-> displayed predicted price
```

FastAPI exists, but Streamlit does not currently call it for inference.

## 3. ML Pipeline

Training uses `House Price India.csv`.

The pipeline:

- loads the CSV with pandas
- uses `Price` as the target
- drops `id` and `Date`
- uses 20 feature columns
- builds a `ColumnTransformer`
- passes numeric columns through
- one-hot encodes categorical/object/bool columns if present
- trains an `XGBRegressor`
- evaluates on a random 20% test set
- saves model, preprocessor, and metadata artifacts

Saved artifacts:

- `artifacts/housing_model.joblib`
- `artifacts/preprocessor.joblib`
- `artifacts/training_metadata.joblib`

## 4. FastAPI

FastAPI is implemented in `app.py`.

Implemented endpoints:

| Endpoint | Method | Purpose |
|---|---|---|
| `/` | GET | Service metadata and endpoint list. |
| `/health` | GET | Model readiness check. |
| `/predict` | POST | Single-property price prediction. |

FastAPI loads model artifacts on startup and validates prediction requests with Pydantic. The request schema exposes the same raw feature names used by the training dataset.

## 5. Streamlit

Streamlit is implemented in `streamlit_app.py`.

It provides:

- sidebar property inputs
- `Property Details` tab
- `Prediction` tab
- `Analytics` tab
- `About` tab

The sidebar collects all 20 model features. The prediction result is a point estimate and model version.

Important V1 fact: Streamlit performs prediction locally by loading `artifacts/housing_model.joblib`. It does not call the FastAPI `/predict` endpoint.

## 6. Analytics

Analytics are implemented in Streamlit and read `House Price India.csv` directly.

Implemented analytics:

- interactive filters
- dataset overview
- missing-value summary
- basic statistics
- price distribution histogram
- price spread boxplot
- correlation heatmap
- top features correlated with price
- filtered CSV download
- model performance display

## 7. Feature Importance

V1 displays XGBoost feature importance from the trained regressor inside the saved pipeline.

The app displays the top 10 features in a horizontal bar chart. This is a technical model diagnostic and is not yet translated into plain-language real-estate explanation.

## 8. SHAP

V1 implements global SHAP explainability in Streamlit.

The SHAP implementation samples up to 500 filtered dataset rows, transforms them with the pipeline preprocessor, runs `shap.TreeExplainer` on the XGBoost regressor, and displays:

- global mean absolute SHAP importance
- SHAP impact scatter chart

The SHAP view explains model behavior over a filtered dataset sample. It does not explain the individual property prediction submitted by the user.

## 9. Model Evaluation

Saved metadata reports:

| Metric | Value |
|---|---:|
| R2 | 0.8933532238006592 |
| MAE | 63,533.23046875 |
| RMSE | 122,590.98094068747 |

These values were verified from `artifacts/training_metadata.joblib` in the V1 audit. They were not recomputed from the saved model during the audit because the audit runtime lacked the required ML packages.

## 10. Known Limitations

- Dataset provenance is UNVERIFIED.
- The dataset filename and INR display imply India, but latitude/longitude values do not correspond to India.
- Currency assumptions are UNVERIFIED.
- Feature definitions are incomplete or missing.
- The app exposes raw model features to users.
- The prediction output is only a point estimate.
- No local explanation is provided for an individual prediction.
- No valuation range or uncertainty estimate is implemented.

## 11. Engineering Limitations

- Streamlit bypasses FastAPI for inference.
- Inference logic and artifact loading are duplicated.
- `streamlit_app.py` is monolithic.
- Feature schema is repeated across training, API, metadata, and Streamlit widgets.
- No tests were found.
- No CI configuration was found.
- No Dockerfile or deployment manifest was found.
- Dependency versions are declared with lower bounds rather than fully pinned compatibility.

## 12. Product Limitations

- V1 is organized around model prediction and analytics, not user decision workflows.
- There are no dedicated buyer, seller, homeowner, or investor journeys.
- There is no property comparison.
- There is no generated property report.
- There are no comparable homes.
- There is no market recommendation layer.
- Technical charts are visible, but plain-language decision support is limited.

## 13. Why V2 Is Necessary

V2 is necessary because V1 proves the technical prototype but does not yet establish product trust.

The next version needs to address:

- verified dataset provenance
- accurate geography and currency framing
- API-first inference or a shared inference boundary
- simplified user-facing property inputs
- valuation ranges
- local human-readable explanations
- user journeys for real real-estate decisions
- stronger evaluation methodology
- tests and deployment discipline

V1 should remain the baseline for what has actually been implemented. V2 should build from this baseline rather than retroactively claiming features that do not exist.
